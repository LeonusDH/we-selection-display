# WE Selection Display

Плагин для [Sponge](https://spongepowered.org) (API 12, Minecraft 1.21.1). Он показывает игроку
его выделение WorldEdit прямо в мире с помощью display-сущностей (`minecraft:block_display`).

- Выделение видит **только тот, кто его сделал**. Сущности существуют лишь на клиенте этого
  игрока: сервер отправляет пакеты ему одному, в мир ничего не добавляется и не сохраняется.
- Клиентский мод (WorldEditCUI) не нужен — у игрока ванильный клиент.

## Что рисуется

| Выделение | Как выглядит | Блок по умолчанию |
|---|---|---|
| pos1 | рамка вокруг блока | красный бетон |
| pos2 (кубоид) | рамка вокруг блока | синий бетон |
| `//sel cuboid`, `//sel extend` | 12 рёбер | лаймовый бетон |
| `//sel poly` | стойки в точках и контур сверху и снизу | жёлтый бетон |
| `//sel cyl` | два эллипса и 4 образующие | оранжевый бетон |
| `//sel ellipsoid`, `//sel sphere` | три «экватора» | пурпурный бетон |
| `//sel convex` | рёбра оболочки | бирюзовый бетон |
| прочее | ограничивающий параллелепипед | белый бетон |

Каждая линия — один `block_display`, растянутый матрицей трансформации в тонкий брусок.
Длинные рёбра режутся на куски (по умолчанию по 16 блоков, по мировой сетке). Рисуются только
куски в радиусе 96 блоков от игрока, но не дальше его дальности прорисовки, причём режется
только ближняя к игроку часть ребра: даже выделение на весь мир не нагружает сервер.
Обновление дифференциальное: при растягивании выделения пересылаются только изменившиеся
куски, одной связкой пакетов. По умолчанию включено свечение своего цвета для каждого типа
линий, поэтому контур виден сквозь блоки, как в WorldEditCUI.

## Установка

1. Нужен сервер SpongeVanilla или SpongeForge с API 12 (Minecraft 1.21.1).
2. Нужен WorldEdit для Sponge **7.3.6–7.3.8**: это последние сборки под API 12, а 7.3.9 и новее
   уже рассчитаны на 1.21.3+.
3. Скачайте jar из [Releases](../../releases) или из артефактов последней сборки в
   [Actions](../../actions) и положите его в папку `mods`.

## Команды

| Команда | Что делает |
|---|---|
| `/selviz` | включить или выключить показ для себя |
| `/selviz on`, `/selviz off` | то же самое явно |
| `/selviz reload` | перечитать конфиг (право `we-selection-display.reload`) |

Конфиг лежит в `config/we-selection-display/we-selection-display.conf`. В нём настраиваются
толщина линий, радиус, длина кусков, лимит сущностей, подсветка, освещение, а для каждого типа
линий — блок (любой, можно с состоянием, например `minecraft:oak_log[axis=x]`) и цвет подсветки
(`RRGGBB`). Значения вне допустимых пределов плагин поправляет сам и пишет об этом в лог.
Выбор игроков `/selviz on|off` хранится до перезапуска сервера.

## Сборка

```
./gradlew build
```

Готовый jar появится в `build/libs/`. Нужен JDK 21; если его нет, Gradle скачает его сам.
При первой сборке VanillaGradle скачивает и подготавливает Minecraft 1.21.1, это занимает
несколько минут.

## Как устроено и как взять в свой плагин

```
src/main/java/dev/selviz/
├── geometry/                 зависит только от worldedit-core
│   ├── SelectionShapes.java  RegionSelector → список отрезков
│   ├── Line.java             отрезок, нарезка ближней части на куски, расстояние до точки
│   └── LineStyle.java        тип линии (pos1, кубоид, цилиндр…)
├── render/                   Sponge + Minecraft
│   ├── ClientDisplays.java   матрица трансформации и пакеты одному игроку
│   ├── SelectionRenderer.java что уже отправлено каждому игроку, дифф
│   └── LineLook.java         блок и цвет подсветки для типа линий
├── SelectionDisplayPlugin.java  жизненный цикл, опрос сессий WorldEdit, команды
├── SessionLookup.java        ключ для поиска сессии WorldEdit по UUID
└── Settings.java             конфиг и проверка значений
```

**Геометрия переносится как есть.** Пакет `geometry` не знает ни о Sponge, ни о Minecraft:
`SelectionShapes.of(selector, curveSegments)` превращает селектор WorldEdit в отрезки `Line`
в мировых координатах, а `Line#splitNear(step, x, y, z, radius, out)` режет на куски только
ту часть отрезка, что рядом с игроком. Границы кусков от положения игрока не зависят, поэтому
их удобно сравнивать между обновлениями. Всем этим можно пользоваться на Paper, Fabric или
где угодно ещё.

**Матрица для отрезка.** Отрезок длиной `L` и толщиной `t` идёт по единичному вектору `n`,
сущность стоит в его начале. Модель `block_display` — единичный куб (0,0,0)–(1,1,1):

```
M = R(+X → n) · T(-t/2, -t/2, -t/2) · S(L + t, t, t)
```

На Paper ту же матрицу можно передать в `BlockDisplay#setTransformationMatrix(Matrix4f)`.

**Видимость одному игроку.** В Sponge API нет способа скрыть сущность от конкретного игрока,
поэтому `ClientDisplays` делает так:

1. создаёт и настраивает `BlockDisplay` обычным Sponge API (`ServerWorld#createEntity` и ключи
   `Keys.BLOCK_STATE`, `Keys.MATRIX`, `Keys.IS_GLOWING` и т. д.), но **не** добавляет его в мир;
2. берёт из него id, UUID и синхронизируемые данные;
3. отправляет игроку `ClientboundAddEntityPacket` и `ClientboundSetEntityDataPacket`, а для
   удаления — `ClientboundRemoveEntitiesPacket`; все пакеты одного обновления уходят одной
   связкой `ClientboundBundlePacket`.

Цвет подсветки в Sponge API 12 не выставить, поэтому поле `Display.DATA_GLOW_COLOR_OVERRIDE_ID`
берётся рефлексией. Если на другой версии игры его не окажется, подсветка будет белой, а в лог
при старте придёт предупреждение.

Классы Minecraft используются только в пакете `render`. Sponge в рантайме работает на
Mojang-маппингах, поэтому достаточно приведения типов, как это делает и сам WorldEdit для Sponge.
На Paper то же самое делается через `Player#hideEntity`/`showEntity` или теми же пакетами.

**Сессию WorldEdit** плагин ищет по UUID игрока (`SessionManager#getIfPresent` с лёгким ключом
`SessionLookup`), поэтому ему хватает `worldedit-core` и не нужен Sponge-адаптер WorldEdit.
